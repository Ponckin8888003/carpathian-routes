# Карпатські маршрути

Вебсервіс планування туристичних маршрутів українськими Карпатами (навчальний проєкт).

Поточний етап (лабораторна 3.2): робота з даними, асинхронні запити й сервіси.
Плани походів читаються й змінюються через сервіс `planService`. Основний режим —
автономний mock із затримкою та збереженням у `localStorage` цього браузера.
Для сумісного REST API підготовлено адаптер (з реальним API не перевірявся).

## Вимоги

Node.js 20.19+ або 22.12+, npm, Git. Маршрутизація: пакет `react-router` (фактична версія вказана в `package.json`, перевірити: `npm ls react-router`).

## Запуск

```bash
npm install
npm run dev
```

Адреса: http://localhost:5173

## Адреси для перевірки

- `/peaks?q=говерла&routes=1` — каталог із фільтрами
- `/peaks/hoverla` — деталі вершини
- `/plans?q=говерла&sort=date-desc` — список планів із умовами
- `/plans/new?peakId=hoverla` — нова чернетка плану
- `/plans/plan-001` — сторінка плану
- `/plans/plan-001/edit` — редагування плану
- `/unknown`, `/peaks/missing`, `/plans/missing/edit` — відсутні сторінки й записи

## Джерело даних і змінні середовища

Скопіюйте шаблон і за потреби змініть значення:

```bash
cp .env.example .env.local
```

| Змінна | Значення | Призначення |
| --- | --- | --- |
| `VITE_DATA_SOURCE` | `mock` (типово) або `api` | Вибір джерела планів |
| `VITE_API_BASE_URL` | Базова адреса API | Потрібна лише для `api`; без секретів |
| `VITE_MOCK_DELAY_MS` | Мілісекунди (типово 600) | Затримка mock-сервісу |

Після зміни `.env.local` перезапустіть `npm run dev`. `.env.local` не комітиться.

Mock-плани зберігаються під ключем `carpathian.plans.v1` у `localStorage` тієї самої
адреси (origin): інший порт дає інше сховище. Початкові плани використовуються лише
коли ключа немає; збережений порожній список не замінюється ними. Щоб почати спочатку,
видаліть цей один ключ у DevTools → Application → Local Storage.

Режим `api` очікує REST-контракт із `docs/project-plan.md` і не підміняє помилки
mock-даними. Змінні `VITE_` потрапляють у клієнтську збірку, тому секретів у них немає.

У режимі розроблення з mock на сторінці списку є панель «Режим перевірки відмов» для
відтворення одноразових помилок. У виробничій збірці її немає.

Обмеження: зміни з іншої вкладки з’являються після «Оновити дані»; транзакцій і
версій запису немає; фактичне підключення REST API не виконано. Для хостингу потрібне повернення `index.html` для клієнтських
маршрутів.
